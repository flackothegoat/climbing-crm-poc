# 模块 2.3A.2：岩点用途分类与完整规格

## 目标

将原来的“型号 → 颜色 → 初始库存”调整为三个彼此独立的业务动作：

1. 按抓握用途创建分类档案。
2. 在分类内创建完整岩点规格。
3. 对选中的完整规格执行到货入库或库存校准。

创建分类和规格都不会自动产生库存。库存只能通过不可变流水发生变化。

2.3B.1 后，八种基础用途由系统自动补齐，普通用户不再需要先创建分类。分类接口和原数据继续保留，用于兼容生命周期和未来 L1 自定义管理。

## 数据层级

| 层级     | 主要字段                                           | 业务含义                         |
| -------- | -------------------------------------------------- | -------------------------------- |
| 用途分类 | 分类编号、名称、抓握用途、说明                     | 浏览、统计和聚合同一抓握用途     |
| 产品款型 | 款型名称、生产商、尺寸、固定方式、外形尺寸、风格   | 表示相同物理造型和产品属性       |
| 完整规格 | 产品款型 + 颜色名称、显示色、供应商货号            | 最小可批量入库、上墙和换线的单位 |
| 库存流水 | 完整规格、库存位置、数量变化、原因、操作者和时间戳 | 只追加，不覆盖历史               |

同一分类下，生产商、款型、尺寸、固定方式和外形尺寸一致时复用产品款型；颜色名称与色值一致时复用颜色规格。完全相同的完整规格不得重复创建。

## 编号与生命周期

- 系统内部关系始终使用不可见 ID，不使用人工编号作为外键。
- 用途分类编号在同一岩馆内唯一。
- 停用分类保留编号、规格和历史，可以恢复，因此编号不会释放。
- 只有全部库存为零、从未产生流水且没有扫描历史的分类可以永久删除。
- 永久删除完成后，原分类编号可以重新创建。
- 如果输入的编号属于已停用分类，接口返回“恢复或永久删除”的明确指引。

## 规格和批量入库

完整规格至少包含：

- 款型或造型名称；
- 生产商；
- 尺寸级别；
- 固定方式；
- 颜色名称和显示色。

供应商货号、造型风格和毫米尺寸为可选补充资料。到货入库必须先选择一个已经存在的完整规格，然后填写数量；系统不根据临时输入的文字字段猜测库存归属。

## 安全迁移

- 新增 `HoldCategory`，不删除原有型号、颜色、余额和流水记录。
- 按岩馆和原抓握类型自动建立用途分类。
- 原型号作为产品款型挂入分类，原颜色作为完整规格继续使用。
- 原停用型号转换为停用规格；已有流水与余额的外键不发生变化。
- 开发数据库存在早期迁移校验漂移时使用 `prisma migrate deploy`，禁止通过重置数据库解决。

## API

| Endpoint                                                    | 用途                         |
| ----------------------------------------------------------- | ---------------------------- |
| `GET /api/holds/categories`                                 | 查询用途分类                 |
| `POST /api/holds/categories`                                | 创建零规格、零库存分类       |
| `GET /api/holds/categories/:categoryId`                     | 获取规格、库存和流水详情     |
| `PATCH /api/holds/categories/:categoryId`                   | 修改分类名称和说明           |
| `POST /api/holds/categories/:categoryId/stop`               | 停用零库存分类               |
| `POST /api/holds/categories/:categoryId/restore`            | 恢复分类                     |
| `DELETE /api/holds/categories/:categoryId`                  | 永久删除未使用分类并释放编号 |
| `POST /api/holds/categories/:categoryId/specifications`     | 创建零库存完整规格           |
| `PATCH /api/holds/specifications/:specificationId`          | 校正规格资料                 |
| `POST /api/holds/specifications/:specificationId/movements` | 入库或库存校准               |
| `POST /api/holds/specifications/:specificationId/stop`      | 停用零库存规格               |
| `POST /api/holds/specifications/:specificationId/restore`   | 恢复规格                     |
| `DELETE /api/holds/specifications/:specificationId`         | 删除未使用规格               |
| `POST /api/holds/movements/:movementId/reverse`             | 撤销错误到货入库             |

## 2.3B 已实现兼容

- 扫描建档、GLB/照片对象存储、受保护的三维预览和全馆初始化批次已经实现，详细规则见 `module-02-hold-scan-initialization-spec.md`。
- GLB 的 SHA-256 作为扫描造型身份，同造型不同颜色可以复用产品造型层。
- 墙面和线路模块引用完整规格 ID，从而准确扣减对应库存。
- 现阶段继续按数量管理，不为每一颗实体岩点单独贴码。
