# 模块 2.3B：岩点扫描建档与全馆初始化

> 2.3B.1 已将扫描升级为通用采集会话，并与手工建档统一。最新入口和安全规则见 `module-02-hold-record-unification-spec.md`。

## 目标

员工扫描一颗代表岩点，上传标准化 GLB 和可选参考照片，再登记现实中完全相同岩点的仓库与已上墙实数。系统以扫描资产作为主要视觉辨识依据，人工名称、颜色、生产商、尺寸和固定方式作为搜索与复核信息。

本阶段不为每一颗普通岩点创建数据库实体。相同完整规格共用一条库存余额，通过不可变库存流水解释数量变化；未来墙面模块只为已上墙位置创建安装明细。

## 领域层级

| 层级     | 主要数据                                     | 业务含义                               |
| -------- | -------------------------------------------- | -------------------------------------- |
| 用途分类 | 抓握类型、分类编号、名称                     | 按使用目的聚合，例如扣点、壶把、斜面点 |
| 产品造型 | GLB 指纹或人工产品键、生产商、尺寸、固定方式 | 表示同一物理造型                       |
| 完整规格 | 产品造型、颜色名称、显示色、供应商货号       | 最小批量库存单位                       |
| 扫描资产 | 对象键、SHA-256、类型、大小、模型元数据      | 主要视觉证据，二进制存 MinIO           |
| 库存余额 | 仓库、已上墙、预留、维护数量与版本号         | 当前快速快照                           |
| 库存流水 | 分区、变化量、前后数量、操作者、来源         | 只追加的事实记录                       |

“一模一样”的实际判断规则为：3D 造型、颜色、尺寸、生产商和固定方式一致。系统以 GLB 的 SHA-256 识别同一扫描造型，再以颜色规格区分同造型的不同颜色。人工资料可以修改，但不会改变扫描造型的内部身份键。

## 全馆初始化流程

1. 日常建档直接使用“新增岩点档案”；首次全馆盘点时才开始初始化批次。
2. 选择系统预置用途和扫描建档方式并创建采集草稿。
3. 上传一个主 GLB；服务端验证二进制文件头、glTF 版本、声明长度并提取网格、材质、纹理和顶点信息。
4. 可选上传 JPEG、PNG、WebP、HEIC 或 HEIF 参考照片。
5. 页面加载受鉴权保护的模型文件，支持旋转和缩放预览。
6. 员工补充辅助规格，填写现场观察到的仓库与已上墙实数。
7. 初始化模式下，数据库事务一次完成产品造型、完整规格、初始化记录、库存余额、差异流水及资产关联；日常模式创建零库存档案。
8. 重复处理其他实物组，最后在没有扫描草稿时完成批次。

已有手工规格无需重新扫描，也可以在详情卡片中登记现场实数并加入当前批次。系统把实数写成库存目标值，而不是盲目增加数量；与原余额的差异用 `INITIAL_BALANCE` 流水保存。

## 安全边界

- 初始化数量必须为非负整数，仓库与已上墙合计至少为 1。
- 同一规格在同一初始化批次只能登记一次。
- 库存余额使用版本号乐观锁；并发变化时要求刷新后重新确认。
- 初始化记录和库存流水不可删除或覆盖。
- 完成批次前必须覆盖当前所有在用岩点档案，且不存在扫描草稿。
- 只有完全没有盘点记录和扫描草稿的空批次可以取消。
- 扫描历史存在时，即使分类零库存且没有流水，也不允许永久删除分类。
- 所有查询从服务端会话推导岩馆，不接受前端传入组织 ID。

## 文件存储

- 二进制文件存入 MinIO 的 `climbingapp-hold-assets` bucket，数据库只保存对象键和元数据。
- 对象键按 `organizationId/hold-scans/scanId/随机文件名` 隔离。
- 单文件最大 20MB；一个扫描草稿只允许一个主 GLB。
- 取消草稿时先在数据库事务中把草稿标记为 `CANCELLED`、资产标记为 `DELETED` 并写审计，再尽力清理对象文件。对象存储临时故障不会让数据库继续指向可读但已丢失的文件。
- 读取资产必须经过会话和岩馆范围校验，不向前端暴露 MinIO 凭据。

## API

| Endpoint                                                     | 用途                     |
| ------------------------------------------------------------ | ------------------------ |
| `GET /api/holds/initialization/active`                       | 获取当前初始化批次和汇总 |
| `POST /api/holds/initialization/batches`                     | 开始初始化批次           |
| `POST /api/holds/initialization/batches/:batchId/complete`   | 完成批次                 |
| `DELETE /api/holds/initialization/batches/:batchId`          | 取消空批次               |
| `POST /api/holds/scans`                                      | 创建扫描草稿             |
| `POST /api/holds/scans/:scanId/assets`                       | 上传 GLB 或照片          |
| `GET /api/holds/assets/:assetId/content`                     | 读取受保护资产内容       |
| `POST /api/holds/scans/:scanId/finalize`                     | 创建扫描规格并登记实数   |
| `DELETE /api/holds/scans/:scanId`                            | 取消扫描草稿并清理对象   |
| `POST /api/holds/specifications/:specificationId/initialize` | 将已有规格加入初始化批次 |

## 2.3A 入库语义优化

- “现场盘点实数”只在进行中的初始化批次显示，用于建立或校准现实快照。
- “到货入库”用于初始化完成后的新采购到货，只能增加仓库数量。
- “处理库存差异”保留给 L1，并要求填写原因。
- 三种操作在界面和后端使用不同入口，避免把目标实数误当成增加数量。

## 后续边界

2.3C 将引入墙面版本、线路和安装明细。换线以整墙事务处理：旧安装明细对应数量从已上墙回到仓库，新方案再从仓库转为已上墙。普通岩点仍按完整规格聚合计数，只有安装位置需要逐条记录。

后端已经预留 `HoldInventoryService.transfer` 原子边界，墙面和线路服务必须调用它，不能由前端连续发送“仓库减一、已上墙加一”两次请求。一次转移会在同一事务中：

1. 校验档案属于当前岩馆且仍在使用；
2. 校验来源库存充足；
3. 同时更新仓库与已上墙余额并增加版本号；
4. 追加来源和目标两条流水；
5. 记录墙面安装或线路分配的引用类型、引用 ID、请求键和审计事件。

未来的墙面安装明细和线路选点只引用 `HoldVariant.id`，不复制颜色、尺寸、厂商或 3D 模型数据。墙面功能成为已上墙数量的权威来源后，应关闭对 `INSTALLED` 分区的普通手工调整入口，只保留 L1 的异常盘点纠偏。

当前不包含手机端直接生成扫描模型、自动识别颜色和生产商、自动统计实物数量、GLTF 外部依赖打包、模型压缩流水线和单颗普通岩点贴码。
