# 模块 2.2——员工与权限管理

## 目标

让 L1 管理员通过邮箱邀请 L2 员工加入当前岩馆，并在看板中维护员工岗位、职责和在职状态。该模块同时为后续岩点、墙面和线路功能提供可靠的操作者身份、固定权限能力和审计基础。

## 角色与权限

`L1_ADMIN` 和 `L2_ADMIN` 表示系统访问等级，不等同于现实岗位。岗位名称通过成员资料中的 `jobTitle` 单独维护。

| 能力                   | L1 管理员 | L2 员工                    |
| ---------------------- | --------- | -------------------------- |
| 查看基础员工目录       | 是        | 是                         |
| 查看员工邮箱和最近活跃 | 是        | 仅本人邮箱，不显示活跃时间 |
| 创建、刷新或撤销邀请   | 是        | 否                         |
| 编辑员工资料和状态     | 是        | 否                         |
| 查看资产               | 是        | 是                         |
| 编辑资产草稿           | 是        | 是                         |
| 发布资产               | 是        | 否                         |

后端使用固定 Capability 执行权限判断，前端隐藏按钮只用于改善体验，不能替代接口权限校验。

## 邀请生命周期

1. L1 输入标准化邮箱创建邀请。
2. 数据库只保存邀请 Token 的 SHA-256 Hash；原始链接仅在创建或刷新成功时返回一次。
3. 同一岩馆和邮箱最多存在一条待接受邀请，默认有效期为 72 小时。
4. 员工打开链接后填写姓名和密码。邮箱已注册时必须验证原账号密码；否则创建新账号。
5. 接受邀请、创建成员关系和创建登录会话在同一数据库事务内完成。
6. 已接受或已撤销的邀请不能再次使用；过期邀请可以由 L1 刷新。

当前 POC 不连接公网邮件服务，管理员复制一次性链接完成演示。未来接入邮件投递器时不需要修改邀请领域模型或接受接口。

## 数据隔离

- 所有员工和邀请查询均从服务端会话推导 `organizationId`，不接受前端指定租户范围。
- `Account.status` 仅表示全局账号安全状态；某个岩馆中的停用状态保存在 `Membership.status`。
- 登录会话关联具体 `membershipId`。停用 L2 时只失效该成员关系下的会话，不影响账号未来加入其他岩馆。
- L2 可以查看同岩馆员工的姓名、岗位、职责和在职状态，但看不到他人的邮箱和最近活跃时间。
- 员工不做物理删除，确保后续资产操作和审计记录始终可以追溯。

## API 契约

| Endpoint                                   | 权限   | 用途                   |
| ------------------------------------------ | ------ | ---------------------- |
| `GET /api/team/members`                    | L1、L2 | 获取组织隔离的员工目录 |
| `PATCH /api/team/members/:membershipId`    | L1     | 修改资料或在职状态     |
| `GET /api/team/invitations`                | L1     | 获取邀请历史           |
| `POST /api/team/invitations`               | L1     | 创建 L2 邀请           |
| `POST /api/team/invitations/:id/resend`    | L1     | 刷新过期时间和原始链接 |
| `POST /api/team/invitations/:id/revoke`    | L1     | 撤销待接受邀请         |
| `GET /api/auth/invitations/:token`         | 公开   | 查看邀请目标和状态     |
| `POST /api/auth/invitations/:token/accept` | 公开   | 接受邀请并建立登录会话 |

## 审计事件

模块记录以下事件，元数据只保留内部 ID 和变更字段，不记录密码或原始 Token：

- `team.invitation.created`
- `team.invitation.resent`
- `team.invitation.revoked`
- `team.invitation.accepted`
- `team.member.updated`

## 本阶段不包含

- 排班、考勤、薪资、绩效和请假。
- 自定义角色、可视化权限编辑器和多门店范围。
- 员工聊天、HR 证件或私人管理备注。
- 公网邮件服务和批量邀请。
