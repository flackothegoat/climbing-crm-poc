# 模块 2.3A——岩点目录与库存基线

> 2.3A.2 已将目录升级为“用途分类 → 完整规格 → 库存流水”。最新规则见 `module-02-hold-category-spec.md`；本文保留为第一版库存基线记录。

## 目标

在不要求闭馆清点、也不要求给每颗普通岩点贴码的前提下，先建立可持续使用的岩点数字目录和数量账。系统记录“某型号、某颜色在不同状态下各有多少件”，并通过不可变库存流水解释每一次数量变化。

本阶段优先解决三个现实问题：

1. 新购岩点可以正常入库并形成审计记录。
2. 岩馆可以把现有仓库和已上墙岩点作为初始基线逐步建档，不要求一次盘清。
3. L1 可以基于盘点结果校准错误余额，L2 不能无痕改账。

## 业务口径

### 型号、颜色和实体

- `HoldModel` 表示共享造型、尺寸和固定方式的岩点型号。
- `HoldVariant` 表示该型号的一个颜色或 SKU，是库存记账的最小单位。
- 普通岩点按数量管理，不为每颗实体创建数据库记录。
- 如果未来需要追踪高价值大型岩体、RFID 或独立维护履历，再增加可选的实体层，不污染当前目录模型。

### 四个库存分区

| 分区          | 含义                               | 2.3A 处理方式                          |
| ------------- | ---------------------------------- | -------------------------------------- |
| `WAREHOUSE`   | 当前可从仓库取用                   | 支持正常到货入库和 L1 校准             |
| `INSTALLED`   | 当前已安装在墙上的聚合数量         | 可录入初始基线；等待 2.3C 关联具体墙面 |
| `RESERVED`    | 已为一次换线预留但尚未安装的数量   | 预留状态已建模；自动流转留到 2.3C      |
| `MAINTENANCE` | 清洗、维修、损坏确认等暂不可用数量 | 状态已建模；维护流程留到后续模块       |

每个颜色的总量满足：

`总量 = 仓库数量 + 已上墙数量 + 预留数量 + 维护数量`

所有分区数量必须为非负整数。正常入库只能增加仓库数量；库存调整由用户填写盘点后的实际数量，可以修正任一分区，但必须填写原因。

## 渐进式建档

真实岩馆不适合为了软件上线而闭馆拆点。2.3A 因此允许创建型号时同时录入“仓库初始数量”和“已上墙基线”：

- 只有仓库数量时，颜色库存标记为 `VERIFIED`。
- 包含已上墙基线时，标记为 `PARTIAL`，表示总量可用但墙面归属仍待核验。
- 后续 2.3C 在正常换线时，以整面墙的拆除和重装事务逐步替换这些聚合基线。

这是一种迁移状态，不代表系统已经知道每颗岩点安装在哪一面墙。

## 数据模型

```text
Organization
  └─ HoldModel（型号）
       └─ HoldVariant（颜色 / SKU）
            ├─ HoldInventoryBalance（当前余额，唯一）
            └─ HoldInventoryMovement（历史流水，多条）
```

`HoldInventoryBalance` 用于快速读取当前状态，`HoldInventoryMovement` 用于解释历史。一次库存操作在同一数据库事务中同时更新余额和写入流水。流水记录操作前数量、变化量、操作后数量、操作者和原因，不提供覆盖或删除接口。

余额带有 `version` 字段。库存调整请求携带 `targetQuantity` 和 `expectedVersion`；后端校验版本后计算差额并使用乐观并发控制。两个员工同时修改同一颜色时，后到请求会收到刷新重试提示，不会静默覆盖前一个结果或偏离用户填写的实际数量。

数据库迁移还包含以下约束：

- 型号尺寸为正数。
- 四个库存余额均不小于 0。
- 流水变化量不等于 0。
- `afterQuantity - beforeQuantity = quantityDelta`。

## 权限

| 能力                 | L1 管理员 | L2 员工 |
| -------------------- | --------- | ------- |
| 查看岩点和库存       | 是        | 是      |
| 创建、编辑型号和颜色 | 是        | 是      |
| 正常到货入库         | 是        | 是      |
| 库存校准             | 是        | 否      |
| 停用零库存型号       | 是        | 否      |

所有查询和写入从服务端会话推导 `organizationId`。接口不接受前端指定租户，也不会返回其他岩馆的型号、余额或流水。

界面使用“停用”管理暂时不再使用的档案，停用不会删除任何历史。L1 也可以永久删除误建或录错的档案：系统自动清零库存，用户界面不再显示，但数据库保留删除存根、删除前快照和清零流水；详细规则见 `module-02-hold-inventory-safety-spec.md`。

## API 契约

| Endpoint                                        | 权限   | 用途                         |
| ----------------------------------------------- | ------ | ---------------------------- |
| `GET /api/holds/summary`                        | L1、L2 | 获取有效目录与库存汇总       |
| `GET /api/holds`                                | L1、L2 | 分页搜索型号目录             |
| `GET /api/holds/:holdId`                        | L1、L2 | 查看型号、颜色和最近库存流水 |
| `POST /api/holds`                               | L1、L2 | 创建型号和首批颜色           |
| `PATCH /api/holds/:holdId`                      | L1、L2 | 修改型号基础信息             |
| `POST /api/holds/:holdId/variants`              | L1、L2 | 添加颜色                     |
| `PATCH /api/holds/variants/:variantId`          | L1、L2 | 修改颜色资料                 |
| `POST /api/holds/variants/:variantId/movements` | 按类型 | 正常入库或库存校准           |
| `POST /api/holds/:holdId/stop`                  | L1     | 停用零库存型号               |
| `POST /api/holds/:holdId/restore`               | L1     | 恢复停用型号                 |

## 前端交互

- 岩点首页展示型号数、颜色数、仓库数量、已上墙数量和待核验批次。
- 目录支持按编号、名称、品牌和抓握类型筛选。
- 详情侧栏按颜色展示四个分区余额，避免在大表格中堆叠编辑控件。
- “到货入库”和“库存校准”是两个明确入口；L2 看不到校准入口。
- 库存流水展示最近 30 条，突出颜色、分区、变化量、操作者和原因。

## 模块衔接

### 2.3B：扫描建档与三维预览（已实现）

- 通过全馆初始化批次上传主 GLB 和参考照片，以扫描资产作为视觉身份。
- 对文件执行格式、大小、SHA-256 和岩馆目录校验，并在前端提供旋转、缩放和失败降级。
- 资产存入 MinIO，数据库只保存对象键和元数据。详细设计见 `module-02-hold-scan-initialization-spec.md`。

### 2.3C：按墙换线

- 建立墙面、墙面版本和安装明细。
- 在一个事务中将旧墙面全部岩点从 `INSTALLED` 移回 `WAREHOUSE`，再将新方案使用的岩点从仓库转为已上墙。
- 流水通过 `referenceType` 和 `referenceId` 关联同一次换线批次。
- 发布新墙面快照后再关闭旧快照，确保营业中读取到的状态始终完整。

## 本阶段不包含

- 手机端现场生成 GLB、自动识别和自动计数。
- 具体墙面坐标、线路归属和整墙换线事务。
- 单颗普通岩点二维码、RFID 或序列号。
- 采购订单、供应商、成本核算和折旧。
- 自动识别图片中的岩点数量、颜色或型号。
