# 模块 2.3A.1——库存安全与概念优化

## 目标

在不破坏 2.3A 已有数据的前提下，明确区分“岩点型号”“同款颜色”和“库存流水”，并为误操作提供可追溯的纠正方式。本模块不通过删除历史来修正库存。

## 领域概念

```text
岩点型号（相同物理造型、尺寸和固定方式）
  ├─ 同款颜色 A（独立库存）
  ├─ 同款颜色 B（独立库存）
  └─ 同款颜色 C（独立库存）
```

- 型号名称不应包含颜色，例如使用“小扣点 S-02”，不使用“黄色小扣点”。
- 同一型号下只能添加物理造型完全相同的其他颜色。
- 显示颜色只用于界面识别，不作为精确测色结果。
- 颜色名称按肉眼分类，允许同一型号下存在多个都叫“黄色”但 Hex 色阶不同的档案；系统用“颜色名 + Hex”区分精确规格。
- SKU 是供应商货号或内部货号，属于颜色版本的可选高级字段。

2.3B 已将主 GLB 和照片作为扫描档案关联到完整规格，并使用 GLB 指纹保持扫描造型身份。2.3C 中，换线安装明细关联完整规格，因为实际定线需要区分颜色。

## 错误入库的处理

库存流水保持追加写入，不允许覆盖或删除。L1 可以对一笔正常到货入库执行“撤销此笔入库”：

1. 系统读取原入库的颜色、分区和数量。
2. 验证该流水属于当前岩馆、尚未撤销且仓库仍有足够数量。
3. 在同一事务中扣减库存并创建 `REVERSAL` 反向流水。
4. 反向流水通过 `reversalOfMovementId` 一对一关联原入库。
5. 原入库在界面中显示“已撤销”，但数据库记录保持不变。

同一笔入库最多撤销一次。如果部分岩点已经流转到墙面、预留或维护，导致仓库数量不足，则拒绝直接撤销，由 L1 使用“调整库存”并填写原因。

“调整库存”要求用户填写现场盘点后的实际数量，不要求理解正负差额。界面显示当前数量、目标数量及“增加/减少几件”，并提供加减按钮。请求同时提交目标数量和页面读取到的库存版本；后端确认版本一致后才计算 `quantityDelta` 并追加库存流水，版本过期则要求刷新后重新确认。

正常入库和库存调整还会提交 UUID 格式的 `requestKey`。余额、流水和审计在同一事务内提交；浏览器遇到超时后使用原请求键重试，后端返回已完成结果，不会重复入账。请求键按岩馆隔离。

## 停用、恢复与永久删除

界面使用“停用”代替容易混淆的“归档”，数据库继续使用兼容的 `ARCHIVED` 状态。

| 操作     | 用户看到的结果                           | 后端处理                               | 恢复      |
| -------- | ---------------------------------------- | -------------------------------------- | --------- |
| 停用档案 | 卡片仍显示“已停用”，不能入库或用于换线   | 保留余额、流水、模型和全部关联关系     | L1 可恢复 |
| 永久删除 | 卡片立即消失，包含停用档案的视图也不显示 | 保留删除存根、删除前快照和库存清零流水 | 不提供    |

停用与删除是不同操作。停用适合暂时不再使用的岩点，永久删除用于重复建档、资料录错或现场数量严重录错。永久删除不要求用户先手动把库存调成零。

永久删除在一个数据库事务内完成：

1. 校验当前用户为 L1，并校验页面读取到的库存版本。
2. 为仓库、已上墙、预留和维护中每个非零位置追加一条 `RECORD_DELETION` 负向流水。
3. 将库存余额全部归零并增加版本号。
4. 把关联模型和图片标记为 `DELETED`，读取接口立即拒绝访问；对象文件暂不物理清除，为后续留存策略预留安全窗口。
5. 写入删除时间、操作账号、原因和完整业务快照，并释放当前档案的有效唯一键。
6. 将扫描草稿取消，写入审计事件，然后把档案从所有正常查询和未来业务选择中排除。

任意一步失败，整笔事务回滚。已删除档案没有面向业务用户的恢复入口；后台保留的数据仅用于审计、事故排查和未来合规留存。相同规格可以在删除后重新建档，新档案会获得新的 ID，不继承旧库存与历史。

墙面和线路模块接入时，业务关系继续关联档案 ID。已删除档案不会进入选点列表；旧线路需要通过快照显示历史名称，不允许重新激活旧档案。

## 权限

| 操作                         | L1 管理员 | L2 员工 |
| ---------------------------- | --------- | ------- |
| 创建和编辑型号、添加同款颜色 | 是        | 是      |
| 正常到货入库                 | 是        | 是      |
| 撤销入库                     | 是        | 否      |
| 处理库存差异                 | 是        | 否      |
| 停用、恢复和永久删除         | 是        | 否      |

权限始终由后端 Capability 校验，隐藏前端按钮不能代替服务端鉴权。

库存写入、停用、删除、初始化和扫描完成使用同一岩馆的短事务锁，并保留余额版本校验。不同岩馆互不阻塞；当前低并发 POC 不引入 Redis 锁、消息队列或微服务。

## API 增量

| Endpoint                                                           | 用途                             |
| ------------------------------------------------------------------ | -------------------------------- |
| `POST /api/holds/movements/:movementId/reverse`                    | 创建关联反向流水                 |

| `POST /api/holds/specifications/:specificationId/restore`          | 恢复停用档案                     |
| `POST /api/holds/specifications/:specificationId/permanent-delete` | 清零库存并永久隐藏档案，保留存根 |

## 前端调整

- 新增型号改为“型号信息 → 首个颜色 → 库存基线”三步向导。
- 移除默认“黄色”，避免无意识创建颜色。
- 型号名称明确提示“不含颜色”。
- “添加颜色”改为“添加同款颜色”，同时提示不同造型应新建型号。
- SKU 收入“更多信息”，显示为“供应商货号（SKU，可选）”。
- 已创建颜色允许校正颜色名称、显示色和供应商货号；该操作只更新档案元数据，不产生或修改库存流水。
- 档案卡片显示停用、恢复和永久删除入口。永久删除会先展示四个库存位置和关联文件数量，要求填写原因并输入“删除”二次确认。
- 流水列表显示撤销状态和撤销入口。

## 本阶段不包含

- 将已有颜色及其历史从一个型号迁移到另一个型号。
- 多笔流水或整次换线批次的一键回滚。
- 自动识别媒体内容和手机端生成扫描模型。
- 墙面安装明细和整墙换线事务。
