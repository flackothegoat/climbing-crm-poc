# 模块 2.1——岩馆数字化看板

## 目标

建立登录后的统一工作空间和清晰的信息架构，为员工、岩点、墙面、线路四个 POC 核心模块提供稳定入口。整体布局参考传统 SaaS 后台的固定侧栏、顶部工作区和主内容区，但视觉语言沿用 Climbing CRM 自身的深绿、浅灰和黄绿色点缀。

## 本次范围

- 登录或注册成功后进入 `/dashboard`。
- 所有看板页面在服务端校验当前会话；未登录或会话失效时返回登录页。
- 左侧导航包含总览、员工管理、资产管理以及四个 Dummy 辅助模块。
- 资产管理可以展开或收起，包含岩点、墙面、线路三个子模块。
- 员工、岩点、墙面和线路页面提供指标、字段目录、演示数据和后续业务链路。
- 日程、营销、数据和设置只提供 Dummy 页面，明确标注不属于当前 POC 演示功能。
- 支持桌面端固定侧栏和移动端抽屉导航。
- 支持退出登录并立即使当前服务端会话失效。

## 核心页面边界

| 页面     | 当前提供                               | 后续功能方向                       |
| -------- | -------------------------------------- | ---------------------------------- |
| 员工管理 | 邮箱邀请、L2 权限、停用和审计基础      | 排班、任务分派和细粒度角色         |
| 岩点     | 型号、颜色、抓握类型、分区库存和流水   | 真实 API、组织隔离、入库与库存校准 |
| 墙面     | 区域、尺寸、点位网格、线路数和状态字段 | 图像采集、基线、配置版本、点位编辑 |
| 线路     | 墙面、难度、定线员、状态和时间字段     | 草稿编辑、审核、发布、下线         |

墙面和线路仍使用模块 2.1 演示数据验证信息架构。员工管理已在模块 2.2 替换为组织隔离的真实 API 数据；岩点管理已在模块 2.3A 接入真实目录、库存余额和流水。详细边界分别见 `module-02-team-management-spec.md` 和 `module-02-hold-inventory-spec.md`。

## 会话 API

| Endpoint                | 用途                               | 成功响应 |
| ----------------------- | ---------------------------------- | -------- |
| `GET /api/auth/session` | 获取当前账号、岩馆、角色和过期时间 | `200`    |
| `POST /api/auth/logout` | 使当前会话失效并清除 Cookie        | `204`    |

看板服务端只从 HTTP-only Cookie 读取会话，不接受前端传入组织 ID。后续所有核心业务查询仍需由服务端身份上下文推导 `organizationId`。
