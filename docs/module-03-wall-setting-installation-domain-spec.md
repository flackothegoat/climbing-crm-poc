# 模块 3：墙面、跨墙段线路与安装事实领域规格

> 日期：2026-08-10  
> 状态：已确认的本地开发基线  
> 上游规格：`module-03-wall-route-observation-spec.md`  
> 明确不包含：摄像头识别算法、自动三维分层算法、Azure 部署、现场施工放样。

## 1. 已确认的现场规则

1. 业务上的“一整面墙”可能包含多个 `WallSegment`。
2. 一条线路可能跨越相邻墙段，不能永久绑定到单一墙段。
3. 所有岩点都安装到墙面已有岩孔，不允许业务系统表达现场新凿孔：
   - 小岩点通常使用一个中心孔；
   - 大岩点可能占用多个既有岩孔。
4. 整墙拆除后、重新安装前，通常可以短暂采集空墙照片或扫描数据。
5. 同品牌、类型、大小和颜色的岩点按一个 `HoldVariant` 管理数量，不为仓库中每一颗松散岩点分配序列号。

## 2. 必须分开的四类事实

```text
墙面几何事实：墙段、几何版本、已有墙孔、模型和测绘精度
定线方案事实：线路版本计划使用哪些岩点、占用哪些孔
现场安装事实：现在实际有哪些岩点安装在哪些孔
库存事实：每个 HoldVariant 位于仓库、已安装、预留或维护区的数量
```

规则：

- 保存或删除定线草稿不改变库存。
- 发布后的线路版本不可原地覆盖。
- 只有现场确认安装或拆卸，才改变 `HoldInstallation` 和库存。
- 扫描识别结果只是观察和匹配建议，人工确认后才成为安装事实。
- 三维文件 checksum 是资产身份，不是岩点产品身份。

## 3. 稳定身份与版本

### 3.1 墙面

- `WallArea`：场馆楼层或大区域。
- `WallSegment`：稳定的物理墙段身份，例如 W06；名称和编号不能因为换线改变。
- `WallSegmentAdjacency`：显式记录两个墙段相邻；跨墙线路不能依赖编号连续性猜测。
- `WallGeometryVersion`：墙段某一次可追溯的几何基线，保存宽高、倾角、坐标系、测绘精度和资产。
- `WallHole`：属于一个几何版本的既有岩孔。墙面几何版本改变时，旧孔位保留供历史线路引用。

换线路不会创建墙面几何版本；只有墙板、倾角、尺寸、孔位或坐标基线发生变化时才创建新版本。

### 3.2 线路

- `Route`：线路的长期业务身份，不以颜色作为主键。
- `RouteVersion`：一次不可变的定线方案快照。
- `RouteVersionWallSegment`：线路版本涉及的一个或多个墙段及其几何版本。
- `RouteHoldPlacement`：计划中的一个岩点位置。
- `RouteHoldPlacementAnchor`：该计划位置占用的一个或多个既有墙孔；恰好一个锚点为 `PRIMARY`。

`Route.wallSegmentId` 在兼容期只表示主要墙段。正式查询线路范围必须通过
`RouteVersionWallSegment` 或位置锚点推导，后续 API 迁移完成后再移除兼容字段。

### 3.3 现场安装

- `HoldInstallation` 表示一颗岩点的一次实际上墙记录，不表示仓库实体序列号。
- `HoldInstallationAnchor` 保存该次安装占用的全部墙孔；活动锚点不能被另一颗活动岩点占用。
- 安装可选关联 `RouteVersion` 和 `RouteHoldPlacement`：现场已有但尚未归属线路的岩点允许为空。
- 拆卸时关闭安装记录和全部锚点，不删除历史。

### 3.4 整墙定线任务

- `WallSettingJob` 表示一次跨一个或多个墙段的拆除、采集、定线和安装工作。
- `WallSettingJobSegment` 固定该任务的墙段范围和操作顺序。
- 一个任务可以关联多个线路版本和安装记录。

状态：

```text
DRAFT
  -> READY
  -> TEARDOWN_IN_PROGRESS
  -> WALL_EMPTY
  -> INSTALL_IN_PROGRESS
  -> COMPLETED
```

`CANCELLED` 只能用于尚未造成现场变化的任务；已经开始拆墙的任务应继续记录和对账，不能通过取消抹掉事实。

## 4. 首次扫描有岩点的墙面

首次录入不要求空墙：

1. 建立墙段和估算或现场校准的几何版本。
2. 保存原始扫描、照片、处理后 GLB 和交付清单，原始资产不可覆盖。
3. 创建 `WallCapture`，并记录本次采集覆盖的多个墙段。
4. 分层算法输出 `WallObservedHold` 和一个或多个候选墙孔锚点。
5. 人工把观察项匹配到已有 `HoldVariant`，或进入独立岩点扫描流程创建新档案。
6. 确认后创建 `HoldInstallation`；未确认观察项不能改变库存。

当前已存在聚合 `installedQuantity`，但尚未分配到墙面。定义：

```text
未分配已上墙数量
= HoldInventoryBalance.installedQuantity
- 同 HoldVariant 的活动 HoldInstallation 数量
```

首次确认已有墙面时，从未分配已上墙数量中认领，不执行第二次
`WAREHOUSE -> INSTALLED`。认领不足时进入库存盘点冲突，不自动补数。

## 5. 独立扫描新购或库存岩点

1. 扫描一颗代表样品。
2. 先匹配现有 `HoldModel / HoldVariant`。
3. 用户明确选择补充已有档案、新增颜色变体或新增型号。
4. 档案确认与到货数量分开提交。
5. 到货数量通过 `RECEIPT` 流水进入仓库。

相同 `HoldVariant` 可以有任意库存数量；只有安装时才为实际占用位置创建逐颗
`HoldInstallation`。

## 6. 整墙拆除、空墙采集与重新安装

1. 创建 `WallSettingJob`，选择多个相邻墙段并冻结开始前快照。
2. 设计新线路草稿，检查计划需求量与可用库存。
3. 进入拆墙状态后，按实际安装记录批量确认下墙：
   - 正常岩点：`INSTALLED -> WAREHOUSE`；
   - 损坏或待清洗岩点：`INSTALLED -> MAINTENANCE`；
   - 关闭安装记录及其活动锚点；
   - 原线路转为非活动状态，但不删除历史。
4. 墙面为空后创建一次 `EMPTY_WALL` 采集，生成精度更高的几何版本或校准资料。
5. 按批准方案安装，逐项或按批次确认实际岩点和孔位。
6. 创建安装记录并执行库存转移，全部核对通过后发布线路和完成任务。

现场工作持续时间长，不能使用一个跨数小时的数据库事务。每个确认命令使用短事务、
组织级锁、幂等请求键和审计；任务状态负责断点续作，最终完成命令负责全量一致性校验。

## 7. 数据库不变量

- 所有业务查询按 Session 中的 `organizationId` 隔离。
- 一个活动墙孔最多属于一个活动 `HoldInstallationAnchor`。
- 一个计划位置至少有一个锚点，且恰好一个 `PRIMARY`。
- 一个活动安装至少有一个锚点，且恰好一个 `PRIMARY`。
- 安装关联的所有孔必须属于任务范围内墙段的有效几何版本。
- 线路版本的所有位置必须落在其 `RouteVersionWallSegment` 范围内。
- 跨多个墙段的线路或定线任务必须形成由 `WallSegmentAdjacency` 连接的连续子图。
- `PUBLISHED` 线路版本不可修改位置或锚点。
- Dummy 位置不允许进入正式安装命令。
- 基线认领不改变库存余额；新安装、拆卸必须同时写安装事实、库存余额、库存流水和审计。
- 删除使用状态和时间戳，不级联删除历史。

## 8. 用户界面术语

- 定线草稿中的删除：`从方案移除`。
- 真实操作：`开始拆墙`、`确认下墙`、`确认安装`。
- 扫描结果：`待匹配`、`系统建议`、`人工已确认`。
- 墙面状态：`测绘估算`、`现场校准`、`空墙已采集`。
- 同一页面必须并列显示“计划数量、实际安装数量、库存可用数量”，不能用“已安装”混称。

## 9. 增量实施顺序

1. 增加几何版本、跨墙段关系、多孔锚点、安装事实和整墙任务数据骨架。
2. 为现有 W06 数据创建兼容几何版本、线路墙段关系和单个主锚点，不改变当前 Demo 行为。
3. 实现现状墙面基线认领及其一致性测试。
4. 实现整墙拆卸命令和 `INSTALLED -> WAREHOUSE / MAINTENANCE` 联动。
5. 实现正式安装命令和库存联动。
6. 重构前端术语、并发控制和正式岩点选择器。
7. 现场数据到达后接入扫描导入适配器；摄像头和分层算法只写观察层，不直接写业务事实。
