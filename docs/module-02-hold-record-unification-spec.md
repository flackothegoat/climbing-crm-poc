# 模块 2.3B.1：岩点档案与采集流程统一

## 目标

解决“手工规格”和“扫描建档”成为两套入口的问题。用户只面对“岩点档案”：扫描录入与手工录入最终创建同一种库存规格，三维模型是档案资产，不是另一类岩点。

## 用户流程

岩点首页只保留“新增岩点档案”主入口：

1. 选择抓握用途。
2. 选择扫描建档或手工建档。
3. 填写同一套颜色、尺寸、生产商、固定方式和造型资料。
4. 创建统一档案。

扫描建档要求上传 GLB，并在提交前显示交互式三维预览。手工建档可以暂时没有模型，之后在档案卡片内使用“补充 3D 扫描”，原档案 ID、库存余额和流水均不改变。

## 用途分类

- 系统自动补齐大把手、小扣点、斜面、捏点、指洞、脚点、大型岩体和其他八种用途。
- 普通建档不要求用户先填写分类编号或创建分类。
- 已存在的自定义名称、编号和停用状态继续保留。
- 停用用途不会被自动恢复，避免绕过用户的生命周期决定。

## 采集会话

原 `HoldScan` 表兼容升级为通用采集会话，使用两种模式：

| 模式                   | 用途                         |
| ---------------------- | ---------------------------- |
| `CREATE_SPECIFICATION` | 上传模型并创建新岩点档案     |
| `ENRICH_SPECIFICATION` | 为已有手工档案补充模型和照片 |

`initializationBatchId` 改为可选。没有初始化批次时，扫描建档创建零库存档案；存在批次时，档案创建和现场实数在同一数据库事务完成。

## 身份与重复判断

- 档案业务身份由生产商、造型名称、尺寸、固定方式、外形尺寸和颜色共同决定。
- SHA-256 只用于文件完整性、相同文件提示和资产追踪，不能证明两次独立扫描来自同一种实物。
- 系统发现业务属性重复时拒绝创建，并引导用户进入已有档案。
- 补充三维模型只关联资产，不修改库存、流水或业务身份。
- 当前一个档案只允许一个主 GLB；后续模型替换应使用资产版本而不是覆盖原文件。

## 安全规则

- 文件上传后锁定用途和建档方式，避免草稿资产关联错误。
- 取消草稿时同时清理对象存储文件、资产元数据和未完成采集记录。
- 已有主模型的档案不能重复补充主模型。
- 具有库存、流水、扫描、资产或初始化历史的档案不能物理删除。
- 全馆初始化继续使用不可变差异流水和余额版本锁。
- L1 与 L2 均可建档和补充模型；停用、恢复、删除和库存差异调整仍由 L1 控制。

## 未来定线契约

墙面和线路必须引用准确的 `HoldVariant.id`，不复制另一套岩点数据。选择器从同一档案读取用途、颜色、尺寸、生产商、三维资产和仓库可用量。提交定线时在事务内创建安装明细，并同步仓库与已上墙余额和库存流水。

档案列表优先展示轻量缩略图；只有选中或展开时加载交互式 GLB，避免大量模型同时加载。
